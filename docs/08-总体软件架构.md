# 总体软件架构

文档版本：0.1  
平台：iOS/iPadOS 16+  
架构风格：本地优先的模块化单体客户端 + 独立在线内容分发层

## 1. 架构目标

- 库存、识别、编辑、制作、出库和备份不依赖在线服务。
- 在线图纸库只负责目录发现、内容下载、版本和下架信息。
- 已下载并校验的图纸可离线打开、复制和辅助拼制。
- 客户端内部按领域模块化，但只构建一个 iOS App 和必要的 Share Extension。
- 首版避免微服务、用户账号、实时协作、消息队列、向量搜索和双重识别管线。
- 关键业务对象可测试，UI、数据库、网络和文件系统通过适配器接入。

## 2. 系统上下文

```text
内容运营人员
    │ 许可审核、资源校验、发布/下架
    ▼
内容发布流水线 ──> 对象存储/CDN ──> iOS/iPadOS App
                         │                 │
                         │                 ├─ 在线目录、预览、下载、更新
                         │                 └─ 本地缓存与离线图纸
                         │
用户本地图片/Files/Share Extension ────────┤
                                           ├─ 本地识别与校准
                                           ├─ 本地库存与补货
                                           ├─ 本地辅助拼制与出库
                                           └─ 本地备份/恢复
```

首版在线库为只读公共内容。收藏、下载记录和制作进度只保存在设备，不上传用户行为。

## 3. 客户端分层

编译时依赖：

```text
Presentation ──> Application ──> Domain
Infrastructure Adapters ───────> Application/Domain 定义的 Ports
AppShell ──> 所有模块（只负责创建与注入具体实现）
```

运行时调用：`Application → Port → Infrastructure Adapter`。业务依赖向内；领域层不引用 SwiftUI、Core Data、URLSession 或具体 CDN，基础设施反向实现业务层定义的端口。

## 4. 客户端模块

| 模块 | 责任 | 明确不负责 |
|---|---|---|
| AppShell | 导航、依赖组装、生命周期、深链 | 业务计算 |
| Palette | 品牌、系列、色号、色差候选 | 库存余额 |
| Inventory | 流水、余额、预留、在途、冲销 | 图纸识别 |
| Pattern | 图纸元数据、版本、紧凑矩阵、用量 | 网络下载 |
| Recognition | 质量门控、透视、网格、OCR、颜色映射 | 保存已确认版本、扣库存 |
| Build | 大画布、分板、高亮、进度 bitset | 修改库存流水 |
| Planning | 多图消耗、缺口、相近色预览 | 静默应用替换 |
| Procurement | 阈值、补货文本解析、采购批次 | 在线下单 |
| Library | 在线目录、搜索、详情、下载、收藏、离线状态 | 图纸识别算法 |
| ContentCache | 内容哈希、校验、磁盘预算、淘汰 | 决定页面排序 |
| Backup | 完整/轻量备份、校验、恢复 | 在线同步 |
| Diagnostics | 本机性能与失败统计、用户主动导出 | 默认上传用户数据 |

## 5. 关键端口

应用层只依赖抽象契约：

- `PatternRepository`：图纸元数据和版本生命周期。
- `PatternMatrixStore`：紧凑矩阵的原子读写与哈希校验。
- `InventoryLedgerRepository`：流水事务和余额重建。
- `BuildProgressStore`：进度 bitset 分块保存。
- `LibraryCatalogRepository`：目录分页、搜索、详情和版本。
- `LibraryPackageStore`：下载、校验、安装、读取和删除内容包。
- `ImageRecognitionService`：本地识别阶段和可校对结果。
- `BackupService`：完整/轻量导出与恢复预览。

这些是架构契约名称，不是代码要求；具体接口在实现阶段依据测试用例确定最小方法集。

## 6. 数据所有权

| 数据 | 真值位置 | 是否联网 |
|---|---|---:|
| 库存流水、采购、预留 | Core Data | 否 |
| 图纸/版本元数据 | Core Data | 否 |
| 图纸矩阵 | Application Support 紧凑文件 | 否 |
| 制作进度 | Application Support bitset/块文件 | 否 |
| 在线目录缓存 | 独立 Core Data persistent store（SQLite 后端） | 更新时需要 |
| 在线可重建资产 | Caches 中按 SHA-256 保存的缩略图/预览 | 下载时需要 |
| 用户固定下载包 | Application Support，独立于自动淘汰缓存 | 下载时需要 |
| 收藏与下载状态 | 本地数据库 | 否 |
| 内置启动内容 | App Bundle | 否 |

在线目录数据不参与库存事务。在线图纸必须先下载、校验并转换为本地只读版本，用户点击“开始制作”时再复制为用户项目。

## 7. 关键业务流程

### 7.1 在线图纸到本地项目

1. Library 获取缓存目录并后台检查更新。
2. 用户浏览、搜索或筛选图纸。
3. 下载管理器获取不可变内容包。
4. ContentCache 校验内容长度、SHA-256、格式版本和许可元数据。
5. LibraryPackageStore 原子安装到内容哈希路径。
6. 用户打开只读预览；开始制作时创建本地 Pattern 和 PatternVersion 引用/副本。
7. PatternUsage 对比本地库存，进入预留、补货或辅助拼制。

### 7.2 本地图纸识别

来源适配器只产生统一的本地图片输入；Recognition 输出可校对草稿。用户确认后 Pattern 创建不可变版本，随后才允许库存规划和制作。

### 7.3 完成与出库

Build 完成会话后请求 Planning 生成出库预览；Inventory 在一个本地事务内创建幂等出库单和流水。Build、Recognition、Library 均不能直接写余额。

## 8. 并发与任务模型

- UI 状态在主执行域更新。
- 图片识别、矩阵统计、哈希和解包使用可取消后台任务。
- 同一内容哈希只允许一个下载/安装任务，其他请求复用结果。
- 元数据网络并发最多 4、内容包最多 2、缩略图最多 4；图片解码 iPhone 2/iPad 4，低内存或严重热状态时降为 1。
- Core Data 使用单一写入协调器；库存事务串行，目录缓存可批量写入。
- 进入后台时暂停非必要预取，完成正在提交的库存事务和进度块写入。

## 9. 错误边界

- 网络失败：显示缓存目录；不影响本地 P0 流程。
- 目录损坏：保留上一版有效目录，拒绝覆盖。
- 内容包校验失败：删除临时文件并允许重试，不进入正式缓存。
- 识别失败：保存草稿并进入手动校准。
- 库存事务失败：整体回滚，出库单和余额均不产生部分状态。
- 矩阵/进度损坏：按块校验，恢复最后完整版本；禁止使用损坏矩阵出库。

## 10. 架构演进门槛

只有达到明确门槛才增加复杂度：

| 变化 | 触发门槛 |
|---|---|
| 静态目录升级查询 API | 在线图纸 > 5,000，或目录压缩后 > 10 MB，或本地搜索 P95 > 150 ms |
| 增加服务端全文搜索 | 多语言/模糊搜索无法在本机达到准确率和性能目标 |
| 增加账号 | 用户明确需要跨设备自动同步，且手动备份不足 |
| 增加投稿后台 | 正式开放第三方投稿和审核 |
| Canvas 升级 Metal | 最低真机 240×240 图纸连续 5 秒低于 45 FPS |
| 增加第二 OCR 引擎 | 指定 PoC 证明 Vision 是主要瓶颈，规则与输入质量优化仍不达标 |

## 11. 禁止的架构捷径

- 不让页面直接访问 Core Data、URLSession 或内容文件路径。
- 不把远端目录对象直接当成本地图纸实体。
- 不以 URL 作为缓存身份；使用内容哈希。
- 不为在线库另建一套图纸矩阵格式。
- 不因在线库加入用户账号或云端库存。
- 不同时维护静态目录和动态 API 两套真值。
- 不在启动主路径同步更新目录、解码大图或计算全库用量。
