# 本地资源规范与研发拆解

文档版本：0.1  
平台：iOS/iPadOS 16+  
约束：色卡、识别规则、启动图纸、库存与用户项目均在本地；无账号、无通用大模型。在线图纸库使用只读目录与 CDN，核心创作不依赖其可用性。

## 1. 本地资源包

应用安装包内置以下资源：

| 资源 | 内容 | 必要元数据 |
|---|---|---|
| 色卡 | 品牌、系列、尺寸、色号、名称、RGB/Lab、材质 | 版本、来源、许可、校验摘要 |
| 识别规则 | 色号语法、易混字符、图例布局、文本解析规则 | 规则版本、适用品牌、变更记录 |
| 豆板预设 | 52/78/104/120 及自定义模板 | 行列、边界、物理尺寸 |
| 灵感图纸 | 缩略图、图纸矩阵、用量、标签、作者 | 授权类型、来源、署名、下架标记 |
| 教程 | 首次使用、网格校准、库存、备份 | 语言、版本、关联页面 |
| 示例数据 | 用于演示的虚构库存和图纸 | `sample` 标记，不能混入正式数据 |

### 1.1 版本规则

- 资源包和每个子资源都有稳定 ID 与语义化版本。
- 色卡更新生成新版本；已确认图纸继续引用旧版 SKU，不被静默重映射。
- 内置图纸更新不覆盖用户创建的副本或制作进度。
- 资源清单带 SHA-256；启动时只校验版本和清单，需要时再按文件校验。
- 首次启动把只读索引导入本地数据库；大图片按需解码，不全量载入内存。

### 1.2 色卡录入质量

- 同一品牌/系列/色号必须唯一。
- 透明、夜光、珠光、温变等属性单独字段记录。
- RGB 仅是显示与近似匹配数据，不代表实物批次绝对颜色。
- 每次色卡导入输出重复色号、缺字段、非法颜色值和跨版本差异报告。
- 首发仅启用完成核验的色卡；未核验资源不能进入正式包。

### 1.3 首发资源预算

| 项目 | 首发目标/上限 |
|---|---:|
| 内置启动图纸 | 50–100 张，全部具有可核验许可 |
| 内置资源压缩体积 | ≤ 120 MB，不含应用可执行文件 |
| 首次解压/索引后资源 | ≤ 250 MB |
| 单张缩略图 | 长边 ≤ 512 px，优先使用系统稳定解码格式 |
| 单张预览图 | 长边 ≤ 2048 px；能由矩阵渲染时不重复内置大图 |
| 缓存预算 | 默认 ≤ 300 MB，可在设置中清理 |
| 低存储保护 | 可用空间低于 500 MB 时暂停生成大型缓存和完整备份 |

许可清单缺失、摘要不匹配或超出包体预算均为构建阻断项。启动内容随 App 更新；在线目录可按用户设置后台刷新，内容包由用户主动下载或明确允许预取。

## 2. 本地存储边界

| 数据 | 保存位置 | 备份 |
|---|---|---|
| 内置只读资源 | App Bundle | 随 App 安装，不重复导出原始包 |
| Core Data 数据库 | Application Support | 导出为独立、版本化数据文件 |
| 原始导入图片 | Application Support/Imports | 完整备份包含；轻量备份不包含 |
| 缩略图与渲染缓存 | Caches | 不备份，可重建 |
| 用户固定下载的在线内容包 | Application Support/LibraryPackages | 完整备份包含；轻量备份只保留下载意图并标记需重新下载 |
| Share Extension 暂存 | App Group/Inbox | 导入后删除，不长期保存 |
| 用户导出文件 | 用户选择的 Files 位置 | 由用户管理 |

删除缓存不得影响用户固定下载包、图纸矩阵、库存、流水或制作进度。原始图片删除前需提示其会影响重新识别，但不影响已确认图纸。

## 3. 研发工作包

### 3.0 依赖关系与并行边界

```text
Sprint 0 基线验证
   ├── Sprint 1–2 豆仓闭环 ───────────────┐
   └── Sprint 3–4 图纸基础 ── Sprint 5–6 识别 ──┐
                    └────── Sprint 7–8 辅助拼豆 ─┤
豆仓闭环 + 图纸基础 ─────── Sprint 9 补货与出库 ─┤
Sprint 0 ─ OL-1 在线目录/缓存 ─ OL-2 内容发布流水线 ─ OL-3 集成
本地闭环 + OL-3 在线库集成 ─────────────── Sprint 11 备份与发布
```

- Sprint 1–2 与 Sprint 3–4 可在数据模型冻结后并行，但不得同时修改库存流水契约。
- 识别依赖图纸矩阵和版本模型，不能先写最终识别引擎再倒推数据结构。
- 辅助拼豆只依赖确认后的图纸矩阵，不直接依赖 OCR 实现，因此可在识别后半段并行。
- 补货与出库依赖稳定的图纸用量和库存事务，需在两个领域验收后集成。
- 备份格式在 Sprint 0 定义版本框架，最终字段到 Sprint 9 冻结后再定版。

全阶段保持以下不变量：库存余额只来自流水；已确认图纸版本不可静默修改；用户数据不依赖网络；任何自动识别结果可定位、可校对、可回退。

### 3.1 Sprint 0：验证基线（2 周）

- 建立 iOS 16 通用工程和 iPad 多栏导航样机。
- 确定 Core Data 模型与迁移策略。
- 完成 120×120、240×240 画布性能样机。
- 收集并双人标注 300 张识别 PoC 数据。
- 核验首发色卡数据与许可。

退出条件：最低真机画布达标；库存模型能重建余额；30–50 张探索集上的 A 类端到端最小识别管线给出 go/no-go 结论；300 张正式 PoC 数据集规范可复现。若自动识别 no-go，1.0 保留手工建图和校准闭环并收缩自动化范围。

### 3.2 Sprint 1–2：豆仓闭环（4 周）

- 色卡浏览、搜索和筛选。
- 入库、出库、盘点、冲销、阈值。
- 预留、在途、采购批次。
- 流水详情和常用色统计。
- 库存单元测试与 10 万流水压力测试。

退出条件：所有 INV 验收用例通过，无负库存静默产生。

### 3.3 Sprint 3–4：图纸基础（4 周）

- 相册/文件/分享导入与草稿。
- 图纸矩阵、版本、用量聚合。
- 手动行列、网格和色号校对。
- 镜像、替换、项目状态和标签。

退出条件：不依赖自动识别也能完整建立图纸并计算用量。

### 3.3A OL-1：在线目录客户端（可与 Sprint 3–4 并行）

- 频道指针、目录 Schema、ETag 和本地目录缓存。
- 在线发现、搜索、筛选、详情和缩略图缓存。
- CatalogRepository 与本地图纸领域之间的桥接契约。

退出条件：本地快照即时展示，目录更新可原子回滚，在线条目尚不能直接修改库存。

### 3.4 Sprint 5–6：本地识别（4 周）

- 输入质量门控、透视和网格检测。
- Vision OCR、色卡字典纠错。
- 单格颜色采样、图例映射、CIEDE2000 候选。
- 一致性校验、异常定位和指标报告。

退出条件：PoC 指标达到文档门槛，否则按输入类型降级为人工校准。

### 3.4A OL-2：内容发布流水线（可与 Sprint 5–6 并行）

- 内容源仓库、元数据/许可 Schema、双人审核门禁。
- 图纸矩阵/用量校验、预览生成、内容包、SHA-256 和签名。
- 对象存储/CDN 的 staging、stable 指针、回滚和撤回清单。

退出条件：同一 URL 字节不可变；缺许可或校验失败不能发布；stable 可一键回滚上一目录。

### 3.5 Sprint 7–8：辅助拼豆（4 周）

- 分块大画布和 iPad 三栏布局。
- 按颜色、按豆板、边框优先和自定义任务。
- 单格/区域进度、恢复、高亮和蚂蚁线。
- Apple Pencil、键盘、VoiceOver。

退出条件：240×240 压力图稳定运行，强制终止后进度可恢复。

### 3.6 Sprint 9：补货与出库（2 周）

- 多图消耗、缺口和预留。
- 本地规则文本解析、补货单和到货。
- 完成出库、幂等、冲销。

退出条件：STOCK 全部用例通过，重复操作不重复扣库存。

### 3.7 OL-3 / Sprint 10：在线图纸库集成（2–3 周）

- 连接 OL-1 目录客户端和 OL-2 发布产物。
- 内容下载、校验、解包、原子安装与本地图纸副本桥接。
- 下载管理、更新、离线打开和撤回清单。
- 内容仓库、双人审核、资源校验、打包、签名和发布/回滚流水线。
- 网络、低存储、损坏包、下架和旧版本专项测试。

退出条件：在线库故障不阻塞启动和本地流程；已下载内容离线可用；校验失败零业务写入；目录可原子回滚。

### 3.8 Sprint 11：备份与发布（2–3 周）

- 版本化备份、校验、预览与恢复。
- 启动图纸、在线稳定目录和教程资源。
- iOS 16/iPad 回归、性能、无障碍和隐私检查。
- TestFlight 元数据、审核说明和签名归档。

退出条件：发布检查表全部完成。

## 4. 任务优先级

| 优先级 | 内容 |
|---|---|
| P0 | 以 PRD 唯一范围矩阵为准：本地色卡、库存台账、在途/预留、A/B 类识别与校准、辅助拼豆、算豆、本地补货解析、出库、启动图纸、在线图纸库、完整/轻量备份、iPad |
| P1 | 公开链接候选提取、硬边像素图推断、普通照片生成、PDF、更多统计、自定义色卡 |
| P2 | 代码型网格、实体豆板照片、多人协作、蓝牙豆板 |

第三方链接导入只作为“获取本地图片候选”的便利入口，不成为 P0 识别引擎依赖。

## 5. 立项前必须确认

1. 首发色卡品牌、系列、尺寸以及数据来源。
2. 启动图纸和在线首发图纸的数量、主题、许可清单与内容发布责任人。
3. 首发是否包含普通照片生成，或只做现成图纸识别。
4. 是否提供一次性买断、免费或 App 内购买；这不改变本地数据架构。
5. 测试最低真机型号和 iPad 型号。
6. App 正式名称、Bundle ID 和开发者账号主体。

## 7. 完成定义

项目 1.0 完成指：用户无需账号即可联网浏览、搜索和下载许可明确的图纸；下载后无需网络即可计算缺口、辅助拼制和出库。用户也可完全离线使用启动图纸与本地导入，并通过完整备份迁移全部本地数据。轻量备份保留已确认矩阵但不支持原图重新识别。所有关键指标达到验收门槛。

## 8. 防止无意义代码堆叠

- 不为每种图纸来源复制一套识别流程；来源适配只负责生成统一的本地图片输入。
- 不为每个豆格创建独立 UI 控件；使用矩阵数据和分层/分块绘制。
- 不维护一份可写余额和另一份独立流水真值；余额缓存必须可由流水重建。
- 不用大模型替代有限色号字典、正则解析、网格几何或明确业务规则。
- 不在首版同时引入 Core Data、文件 JSON 和另一套数据库保存同一实体。
- 不因某张异常图添加全局特殊分支；异常样本进入数据集，以输入类型、置信度和校准步骤解决。
- 不在识别层直接扣库存；识别只产出图纸版本，出库由独立库存事务完成。
- 不把 P1/P2 能力塞入 P0 页面占位；未交付功能不显示无效入口。
