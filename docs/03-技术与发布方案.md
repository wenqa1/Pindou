# 技术与发布方案

文档版本：0.1  
平台基线：iOS/iPadOS 16+  
运行约束：识别、色卡、库存、统计、文本解析与制作全部在本机完成；在线图纸库是独立只读内容分发层。在线库故障不得影响本地功能；不接入通用 AI 大模型或云端推理。

## 1. 技术目标

- 同一工程支持 iPhone 和 iPad，iPad 提供横屏、分屏、键盘与大画布体验。
- iOS 16 的设备能够完成库存、图纸识别、编辑、辅助拼制、统计、备份和恢复。
- 用户图片、库存、制作记录默认不离开设备。
- 大图采用分块加载和局部重绘，避免一次创建上万个独立视图。
- 所有库存变更和图纸版本可追溯、可冲销、可恢复。

## 2. 总体架构

```text
在线目录/CDN → 下载/签名与哈希校验 → PatternImportBridge ─┐
系统分享/相册/文件 → 本地识别与校准 ──────────────────────┤
内置启动集 ──────────────────────────────────────────────┤
                                                           ▼
                                                  本地图纸版本与用量矩阵
              │
              ▼
        图纸版本与用量矩阵
        ├──────────┬──────────┐
        ▼          ▼          ▼
     辅助拼制   消耗计算    图纸编辑
        │          │          │
        └──────────┴──────────┘
                   │
                   ▼
       库存台账→预留→补货→出库
                   │
                   ▼
          本地备份/用户主动导出
```

建议按领域拆分模块：应用壳、在线图纸库、内容缓存、色卡、库存、图纸、识别、画布、制作会话、补货、统计、备份。模块之间通过稳定接口交互；完整模块和依赖规则见《总体软件架构》。

## 3. iOS 16 兼容选型

| 领域 | 选型 | iOS 16 说明 |
|---|---|---|
| UI | SwiftUI + NavigationStack；画布首选单一 Canvas/CGContext 绘制路径 | 真机基准不达标时才评估 Metal，不并行维护多套画布 |
| 持久化 | Core Data + SQLite | SwiftData 需要更高系统；开启轻量迁移并为备份定义独立格式 |
| 并发 | Swift Concurrency；底层图像任务配合 OperationQueue/Accelerate | 支持任务取消、进度和优先级 |
| 图片选择 | SwiftUI PhotosPicker/PHPickerViewController | iOS 16 可用，只读取用户选择的资源 |
| 文件导入 | UIDocumentPickerViewController | 支持图片与本地备份文件 |
| 系统分享 | Share Extension | 接收 URL、图片和文本，写入 App Group 暂存区 |
| OCR | Vision 的 VNRecognizeTextRequest | 本地运行，返回候选、置信度和位置 |
| 文档四角 | VNDetectDocumentSegmentationRequest/VNDetectRectanglesRequest | 自动结果作为初值，保留手动四角修正 |
| 图像处理 | Core Image、vImage/Accelerate | 本地阈值、卷积、色彩转换与缩放 |
| 色彩管理 | ColorSync/Core Graphics + CIEDE2000 | 色卡 Lab 值可预计算 |
| 导出 | ImageIO、Core Graphics、PDFKit | PNG、PDF 和 JSON/ZIP 备份 |
| 日志 | os_log | 不记录原图、剪贴板全文和用户备注 |

部署目标固定为 16.0。持续集成至少包含一个 iOS 16.x 模拟器构建检查，并以最低支持真机做性能验证。

## 4. 本地数据设计

### 4.1 核心实体

| 实体 | 关键字段 | 约束 |
|---|---|---|
| Brand | id、名称、版本、来源 | 名称在当前库唯一 |
| Palette | id、品牌、系列、尺寸、版本 | 色卡升级不覆盖旧版本 |
| BeadSKU | id、paletteId、色号、名称、sRGB/Lab、材质 | `paletteId + 色号` 唯一 |
| InventoryLedger | id、SKU、类型、数量、前后余额、关联单、时间 | 生效后不可静默编辑，只能冲销 |
| InventorySnapshot | SKU、现存、预留、在途、更新时间 | 可重建的查询缓存，不是真值源 |
| PurchaseBatch | id、状态、供应商、下单/到货时间 | 未到货只增加在途 |
| PurchaseLine | batchId、SKU、订购、到货数量 | 允许分批到货 |
| Pattern | id、标题、来源、状态、当前版本 | 私有导入默认不公开 |
| PatternVersion | id、patternId、行列、方向、识别参数、matrixFile、matrixHash、版本号 | 已确认/已出库版本锁定 |
| PatternUsage | versionId、SKU、数量 | 从矩阵文件派生，可重建 |
| BuildSession | id、versionId、模式、progressFile、更新时间 | 进度用 bitset/紧凑块，支持中断恢复 |
| Reservation | id、图纸/清单、SKU、数量、状态 | 影响可用量，不改现存量 |
| StockOrder | id、出库状态、关联图纸版本 | 幂等键防重复扣减 |
| ImportDraft | id、原始资源引用、当前步骤、校准参数 | 向导退出后恢复 |

### 4.2 数量规则

- 现存量 = 所有已生效库存流水的数量之和。
- 可用量 = `max(现存量 - 有效预留量, 0)`。
- 在途量 = 未完成采购行的未到货数量。
- 图纸用量从当前确认版本的非空单元格聚合。
- 出库、冲销、到货、盘点在单个 Core Data 写事务内完成。
- 所有数量使用 64 位整数；输入上限由产品规则限制，防止溢出或误粘贴。

### 4.3 图纸矩阵与进度存储

- Core Data 只保存图纸、版本、用量和文件引用等元数据，不把每一个豆格建成独立实体。
- 每个图纸版本使用带格式版本、行列、色卡引用和 SHA-256 的紧凑矩阵文件；单元格保存局部色号索引、空位和置信状态。
- 已确认版本的矩阵不可变；编辑采用写时复制，保存成功后原子替换版本引用。
- 制作进度与图纸矩阵分离，使用 bitset 或分块位图；单次点格先更新内存，按短间隔、进入后台和退出页面批量落盘。
- 每个进度块带序号和校验；异常终止时读取最后完整块，不使用逐格 Core Data 写入。
- PatternUsage 是可重建缓存；矩阵哈希不一致时禁止出库并触发重算/修复。

### 4.4 内置内容

- 色卡、解析规则和 50–100 张已许可启动图纸作为版本化资源随 App 打包。
- 内置内容包含内容版本、来源、许可、校验摘要和最低应用版本。
- 更新 App 时通过迁移清单增加内容；不覆盖用户修改过的副本。
- 在线图纸库通过版本化目录、对象存储/CDN 和内容寻址包扩展内容；下载并校验后进入同一本地图纸矩阵格式。

### 4.5 在线目录与内容缓存

- 在线目录缓存与用户正式数据分离，可删除、可重建。
- 收藏、已下载记录和从在线图纸创建的项目属于本地用户数据并进入备份。
- 资产按 SHA-256 存储；相同字节只保存一份，内容改变自动失效。
- 目录后台刷新不进入启动关键路径；目录更新失败继续使用上一版有效快照。
- 详细内容包、缓存、许可和下架规则见《在线图纸库架构》。

## 5. 本地图纸识别

识别引擎采用确定性管线：

1. 输入质量检查与类型判定。
2. 有效区域、图例区和四角校准。
3. 透视展开、网格线检测、周期补全和行列确认。
4. Vision OCR 读取图例色号/数量。
5. 色卡字典纠正常见字符混淆。
6. 每格内缩区域做稳健颜色采样。
7. 带图例图优先匹配同图色块；无图例图用 CIEDE2000 排序品牌色卡候选。
8. 用网格总数、逐色数量、色卡合法性和置信度做一致性校验。
9. 用户确认后生成不可变图纸版本。

详细边界和指标见《图纸识别逻辑与可行性验证》。识别线程在后台队列运行，按阶段回报进度并支持取消；中间图像使用自动释放池和缩小副本，原图只保留一份。

首发技术栈固定为 Vision + Core Image/Accelerate + ColorSync；不同时集成 OpenCV、ML Kit 或第二套识别管线。只有 Sprint 0 指定 PoC 指标未达标，且定位到现有系统能力缺口时，才对一个备选方案做隔离验证。

## 6. 本地补豆文本解析

不使用自然语言大模型，采用可解释的本地解析器：

1. 文本规范化：统一全半角、大小写、中文标点和换行。
2. 行切分：换行、逗号、分号和连续空格作为候选分隔符。
3. 字段词典：品牌、系列、到货/未到货同义词、数量单位。
4. 色号匹配：只接受当前内置色卡存在的色号；处理 `F22×1000`、`F22 1k`、`F22:1000` 等模板。
5. 歧义检测：同一色号跨品牌、缺数量、多个数字时标红。
6. 预览确认：用户确认品牌、SKU、数量和状态后才写入采购批次或库存流水。

解析器以规则版本号记录在导入单中。新规则不会静默改变历史结果。

## 7. 大画布与 iPad 适配

### 7.1 渲染策略

- 图纸单元存为紧凑矩阵文件；视图只绘制当前可见区域。
- 网格、颜色、文字、进度和辅助线分层绘制，状态变化只重绘受影响图层。
- 缩放级别：远景只画色块，中景画网格，近景再画色号/符号。
- 104×104、120×120 不是性能上限；测试至少覆盖 240×240 压力样本。
- 不为每个豆格创建 SwiftUI View、UIButton 或独立 CALayer。

### 7.2 iPad 交互

- 支持横竖屏、Split View、Slide Over 和多窗口尺寸变化。
- Regular 宽度采用侧栏 + 内容 + 检查器布局；Compact 宽度退化为分层导航。
- 支持 Apple Pencil 点选/框选、双指缩放平移、键盘撤销重做和方向键移动。
- 工具栏可固定在左/右侧，避免遮挡画布；弹窗使用 iPad 合理锚点。
- 辅助拼豆允许屏幕常亮，但默认关闭并解释耗电影响。

## 8. 数据备份、恢复与迁移

- 自动保存到应用沙盒；关键事务完成后持久化。
- 完整备份包含 manifest、色卡引用、库存流水、图纸矩阵、制作进度、原始导入图片和用户固定下载的在线内容包，可支持重新识别及离线恢复已下载图纸。
- 轻量备份不含原始导入图片或在线内容包；恢复后库存、已确认矩阵和制作进度可用，下载意图保留但安装状态变为“需重新下载”。
- 备份包包含 SHA-256 清单；导入前校验完整性和格式版本。
- 导入先在临时存储中解析并显示新增、重复、冲突、无效项；确认后再事务性合并。
- 提供“仅导入图纸”“仅导入库存”“恢复完整/轻量备份”选项，并在确认页说明能力差异。
- 删除项目进入“最近删除”，保留 30 天；库存流水不随图纸删除。

## 9. 隐私与安全

- 不要求账号；不上传图纸、库存、制作照片或剪贴板内容。
- 相册采用系统选择器；相机、照片写入、文件访问均按需请求。
- Share Extension 只读取用户明确分享的当前项目，处理后清除 App Group 暂存文件。
- 外部链接是可选联网来源，不属于核心离线闭环。必须显示目标域名，由用户主动导入；本机适配器限制白名单、响应大小、图片 MIME 和重定向次数，下载为本地候选后再识别。
- 备份默认不包含外部登录信息或系统令牌。
- 如加入匿名崩溃统计，必须单独说明、最小化字段并允许关闭。

## 10. 性能预算

| 场景 | 目标设备/条件 | 预算 |
|---|---|---:|
| 冷启动到可操作 | iOS 16 最低验证真机 | P95 ≤ 2.5 秒 |
| 温启动到可操作 | iOS 16 最低验证真机 | P95 ≤ 0.8 秒 |
| 在线目录缓存首屏 30 条 | 本地缓存 | P95 ≤ 300 ms |
| 在线冷网络首屏 | 20 Mbps、RTT 100 ms | P95 ≤ 1.8 秒 |
| 1 万条目录本地搜索 | 输入防抖后 | P95 ≤ 150 ms |
| 10 MB 内容包下载+校验 | 20 Mbps、RTT 100 ms | P95 ≤ 7 秒 |
| 50 MB 内容包解包+安装 | 已下载，最低真机 | P95 ≤ 4 秒，额外峰值内存 ≤ 64 MB |
| 打开 120×120 图纸 | 已在本地 | P95 ≤ 1 秒 |
| 打开 240×240 图纸 | 已在本地 | P95 ≤ 1.5 秒 |
| 画布平移/缩放 | 120×120 | 交互期间目标 55–60 FPS，最低不持续低于 45 FPS |
| A 类 104×104 图纸识别 | 清晰本地图片 | P95 ≤ 8 秒 |
| 单格进度保存 | 本地事务 | P95 ≤ 100 ms，UI 不阻塞 |
| 100 张图纸消耗汇总 | 已有用量缓存 | P95 ≤ 1 秒 |
| 10 万条库存流水统计 | 本地数据库 | P95 ≤ 2 秒 |

最低真机在 Sprint 0 确定，至少选择一台能运行 iOS 16 且内存较低的 iPhone，以及一台 iPad。

性能规则：启动关键路径不发网络请求；搜索、缩略图解码、哈希、解包、识别和矩阵聚合不占用主线程；主线程单任务 P95 ≤ 16 ms，超过 100 ms 视为缺陷。在线性能测试方法见验收文档。

## 11. 发布与 IPA

### 11.1 构建前提

- macOS、受支持的 Xcode、Apple Developer Program 团队。
- 唯一 Bundle ID、签名证书、描述文件、应用图标、启动配置和隐私说明。
- iPhone/iPad 两类截图、审核说明、支持网址和隐私政策。

### 11.2 分发路径

| 场景 | 方式 | 产物/限制 |
|---|---|---|
| 团队开发验证 | Development | 注册设备安装，调试签名 |
| 小范围指定设备 | Ad Hoc | 导出签名 IPA；设备 UDID 需登记 |
| 内外部测试 | TestFlight | 上传 App Store Connect；构建有效期与审核规则按 Apple 当前要求 |
| 正式发布 | App Store | 提交审核后面向用户分发 |

Apple 官方流程要求先归档，再选择 TestFlight/App Store 或自定义分发。最终是否直接交付 IPA 取决于签名方式和设备范围；项目文档不包含证书或二进制。

### 11.3 审核重点

- 内置灵感库内容的版权来源、许可清单和联系渠道。
- 在线图纸库的内容许可、下载说明、缓存、下架、投诉和隐私披露。
- 第三方平台链接导入是否得到相应服务条款允许。
- 相册/文件权限文案是否与实际用途一致。
- 用户投稿、多人协作或商城不属于当前本地架构；启用前需单独架构与审核决策。
- 订阅或数字内容解锁需遵循 App Store 内购规则。

## 12. 技术里程碑

1. Sprint 0：iOS 16 工程基线、Core Data 模型、120×120 画布性能样机、300 张识别 PoC 数据集规范。
2. Alpha：库存台账、图纸矩阵、手动校准、辅助拼制、备份恢复。
3. Beta：本地 OCR/网格/颜色识别、补豆文本解析、多图核算、iPad 分屏与无障碍。
4. RC：迁移、压力、崩溃、内容许可、隐私清单、TestFlight 回归。
5. 1.0：App Store 提交；如需 Ad Hoc，同步产出受控签名 IPA 和安装说明。
