## 2. 客户端逻辑架构树

```text
AppShell
├─ Root navigation / scene lifecycle
├─ DependencyContainer
└─ Feature composition
   ├─ Presentation
   │  ├─ SwiftUI View
   │  ├─ @Observable screen state
   │  └─ Type-safe route
   ├─ Application
   │  ├─ Use case
   │  ├─ Command / Query
   │  └─ Port protocol
   ├─ Domain
   │  ├─ Entity / Value Object
   │  ├─ Invariant / Policy
   │  └─ Domain event / Error
   └─ Infrastructure
      ├─ Core Data adapter
      ├─ File adapter
      ├─ URLSession/CDN adapter
      └─ Vision/Image adapter
```

编译方向始终指向内层。运行时由 AppShell 注入具体适配器，Application 通过 Port 调用 Infrastructure；Domain 不知道适配器存在。

## 3. 端到端数据流

```text
本地导入/分享
    └─> Recognition ──草稿──> Pattern ──用量──> Planning
                                         │           │
                                         │           └─缺口──> Procurement
                                         └─项目──> Build ──完成预览──> Inventory Ledger

签名静态目录/CDN
    └─> Library ──下载──> ContentCache ──校验安装──> 只读 Pattern
                                                      └─开始制作──> 本地项目副本

Core Data 元数据 + Application Support 矩阵/进度
    └─> Backup ──校验──> 完整备份或轻量备份
```

在线库失败时，本地识别、库存、制作、出库和备份链路保持可用。

## 4. 模块依赖白名单

| 调用方 | 可依赖 | 禁止直接依赖 |
|---|---|---|
| Presentation | 同 Feature 的 Application/Domain、Shared UI | Core Data、URLSession、具体文件路径 |
| Application | Domain、Packages 中的稳定契约 | SwiftUI、UIKit 页面、具体数据库实现 |
| Domain | Swift 标准库和必要值类型 | Apple UI/持久化/网络框架、其他 Feature UI |
| Infrastructure | 本 Feature 的 Application/Domain Ports、Platform | 反向驱动页面状态 |
| Platform | Apple 系统框架、Packages | 具体业务页面和业务流程 |
| AppShell | 各 Feature 的公开组装入口、Platform | 业务规则和算法细节 |
| ContentPipeline | Packages/ContentContracts、PatternFormat | iOS 页面与本地用户数据 |

跨 Feature 协作通过 Application 用例与稳定 ID/值对象完成，不直接读取对方的 Core Data 实体。

## 5. iPad 适配落点

- AppShell 负责 iPhone 单栏与 iPad `NavigationSplitView` 的组合，不在业务模块复制两套页面。
- Presentation 保持页面状态与布局分离；列表选择、详情和工具面板通过稳定路由状态协调。
- Build 画布将渲染数据与 SwiftUI 控件拆开，便于 iPad 大画布、键盘、指针和多窗口扩展。
- 图片解码并发与缓存预算由 Platform/SystemServices 根据设备与热状态提供，不散落在页面。
- 所有关键路径在 Tests/UITests 中分别覆盖紧凑宽度与常规宽度。

## 6. 首批实现顺序

1. 已建立 XcodeGen iOS target、测试 target 和 AppShell；首次 Codemagic workflow 负责验证生成与编译。
2. 完成 PatternFormat 最小契约与 120×120、240×240 基准样本。
3. 完成 Pattern + Build 垂直切片，验证矩阵打开、缩放、高亮和进度保存。
4. 完成 Recognition PoC，接入可校准草稿，不直接写已确认图纸。
5. 完成 Inventory Ledger 垂直切片和幂等出库。
6. 完成 Library + ContentCache 静态签名目录 PoC。
7. 接入 Planning、Procurement、Backup 和 Diagnostics。

每一步先固定协议与验收样本，再增加具体 UI；共享抽象只在至少两个模块出现相同稳定需求后提取。
