# 图纸识别逻辑与可行性验证

文档版本：0.1  
日期：2026-08-27  
结论等级：**方案可行，但属于“限定输入 + 自动识别 + 人工校准”的工程问题；不应承诺任意网络图片全自动准确识别。**

## 1. 验证结论

现有 PRD 提出的“框选图例—核对总数—校准网格—识别色号—人工校对”总体可行，且与公开可验证的常用计算机视觉能力一致。需要做三项修正：

1. 按输入类型分流，不能用一套算法处理所有图纸。
2. 色号识别应以“图例 OCR + 单元格颜色归类”为主，避免对每个格子重复 OCR。
3. 自动识别率必须通过真实样本集测量后确定；首版发布门槛应使用准确率、覆盖率和人工校对耗时，而不是先写固定宣传值。

### 1.1 分能力结论

| 能力 | 可行性 | 结论 | 主要限制 |
|---|---|---|---|
| 图片候选获取 | 中 | 本地图片、文件和系统分享稳定；粘贴第三方链接取图是来源适配问题 | 页面结构、登录、反爬、授权和内容有效期 |
| 图纸区域/四角检测 | 高 | 正视截图和边界清晰图片可自动完成；拍照可用四角检测后透视校正 | 遮挡、弯曲纸面、复杂背景、裁边 |
| 规则网格检测 | 高 | 清晰直线网格可用边缘 + 形态学 + Hough/投影峰检测 | 低对比度、虚线、压缩、摩尔纹、线被色块/文字打断 |
| 无网格像素块推断 | 中 | 对整数倍放大的硬边像素图可估计周期 | 抗锯齿、缩放非整数倍、渐变和压缩会破坏周期 |
| 图例色号 OCR | 中高 | Latin 字母 + 数字的短色号适合 OCR，再用色卡字典约束 | `0/O`、`1/I/l`、`5/S`、`8/B`、小字和艺术字体 |
| 中文说明 OCR | 中 | 首发使用 Apple Vision 中文识别 | Apple 文档说明中文不支持 language correction/customWords；不能依赖它纠正品牌词 |
| 单元格颜色识别 | 高（截图）/中低（实拍） | 截图可用稳健采样 + 色差匹配；实拍需白平衡/光照校正 | 网格线、格内文字、阴影、屏幕偏色、豆子批次色差 |
| 图例颜色到色号映射 | 高 | 在同一张图内比较色块比直接匹配官方 RGB 更稳 | 图例色块太小、色块有文字覆盖、同色号印刷偏差 |
| 总豆数校验 | 高 | 网格非空数与图例数量总和可做强一致性校验 | 只能发现不一致，不能单独定位所有错误 |
| 相近色推荐 | 高（推荐） | CIELAB + CIEDE2000 可作为候选排序基础 | 数字色差不是实物等价证明，最终需人工确认 |
| 完全自动无校对 | 低 | 不应作为首版目标 | 输入差异和近似色使静默错误不可接受 |

## 2. 市面常见识别逻辑

### 2.1 公开可确认的产品能力

- 拼豆大王公开宣称上传/导入图纸后进行 AI 色号和数量识别，并提供无图例图纸识别回填、行列拆分、高亮和库存对比。
- 拼豆绘、拼豆艺术、爱拼豆、Perlypop、Beads Creator 等公开提供图片转图纸、品牌色号匹配和用量统计。
- 开源拼豆工具普遍采用“图像缩放或网格采样 → 每格代表色 → 色板最近色 → 计数”的管线；代表实现使用单元格主色、RGB 距离或 CIELAB/CIEDE2000，并可选抖动、背景检测和小区域合并。

这些资料能证明相关能力在产品层面常见，但商业 App 并未公开足够细节来确认其具体模型。下述逻辑是基于公开产品行为、开源实现和官方视觉 API 形成的工程归纳。

### 2.2 四类输入必须分流

| 类型 | 特征 | 推荐逻辑 | 首版支持 |
|---|---|---|---|
| A. 带图例的彩色网格图 | 有规则格线、格内颜色、旁边有色号—色块—数量 | 网格检测 + 图例 OCR + 同图色块匹配 + 计数校验 | P0，重点类型 |
| B. 无图例的彩色网格图 | 有规则格线与颜色，没有色号表 | 网格检测 + 单元格采样 + 用户选择品牌色卡 + 最近色候选 | P0，需明确“推测色号” |
| C. 硬边像素图 | 无格线，像素块规则放大 | 周期/缩放倍数估计 + 用户确认行列 + 单元格采样 | P1；P0 可要求用户输入行列 |
| D. 普通照片/插画 | 连续色、无固有网格 | 裁剪 + 缩放/量化 + 色板映射，生成新图纸 | P1；这是“生成”而非“识别原图纸” |
| E. 仅色号文字网格 | 格子中只有代码或符号，缺少稳定色块 | 网格切分 + 逐格 OCR/符号分类 + 字典约束 | P2 或限定模板；误差和算力成本更高 |
| F. 实体豆板照片 | 圆豆、孔洞、反光和透视 | 圆/环检测或专用模型 + 光照校正 | P2，不纳入首版 |

## 3. 推荐识别管线

### 3.1 阶段 0：输入质量门控

进入识别前先计算并提示：

- 分辨率和预计单格像素尺寸；单格过小则要求更高清图片。
- 模糊度、压缩块、过曝/欠曝比例。
- 图纸是否完整、四边是否可见。
- 是否疑似截图、扫描件、拍照或普通插画。

门控结果不是简单成功/失败，而是：可自动识别、建议手动校准、建议更换图片。

### 3.2 阶段 1：区域与透视

1. 用户框选图纸有效区域和图例区域。
2. 对拍照输入检测最大四边形；Apple Vision 的文档分割请求可返回文档四角。
3. 使用四点单应性做透视展开，使横纵网格接近正交。
4. 在 UI 中叠加四角和边缘，用户可拖动修正。

判断：技术成熟、可本地执行。自动四角只是初值，人工锚点必须保留。

### 3.3 阶段 2：网格检测

建议使用混合方案，不只依赖单一 Hough 参数：

1. 灰度化、局部对比度增强和自适应阈值。
2. 用水平/垂直形态学核提取长线。
3. HoughLines/HoughLinesP 检测候选直线。
4. 将近似平行且位置接近的线聚类去重。
5. 对水平和垂直投影做周期峰检测，补全被颜色或文字打断的线。
6. 求交点并检查：行列间距的变异、正交误差、边界覆盖率。
7. 给出行列数和置信度；低置信度进入九宫格/四角/行列数人工校准。

不要把“8×8”解释成降低识别分辨率；它应是局部校准窗口或锚点密度。最终仍需保留每一个豆格。

### 3.4 阶段 3：图例 OCR 与结构化

1. 只对用户框选的图例区 OCR，减少图案区域干扰。
2. OCR 返回文本、候选、置信度和位置框。
3. 使用色卡字典约束语法，例如 `字母前缀 + 1–3 位数字`，并保存多个候选。
4. 对易混字符建立上下文纠错表，但只在候选属于所选色卡时自动纠正。
5. 根据空间位置把色号、色块、数量配对：同一行优先，再按距离和对齐关系评分。
6. 无法唯一配对的行进入人工确认。

推荐默认使用 Apple Vision 准确模式。色号主体是拉丁字母和数字，可用所选品牌色卡做应用层字典校正；中文说明识别只作辅助，因为 Apple 明确说明中文不支持 language correction/customWords。

首发只使用 Apple Vision。若 Sprint 0 的指定 PoC 指标未达标，先通过输入质量门控、字典约束和人工校准收敛范围；只有证据表明 OCR 引擎本身是主要瓶颈时，才隔离验证一个随 App 打包的本地备选，不并行维护双引擎。

### 3.5 阶段 4：单元格代表色

对每个校准后的格子：

1. 忽略靠近格线的外圈像素。
2. 检测并降低深色文字/符号像素的权重。
3. 对剩余像素在 CIELAB 中求中位数或主簇中心，不使用单个中心点。
4. 保存格内颜色离散度；离散度过高表示格子可能错位、含文字或不是单一色。
5. 透明/空白与白色豆分开建模，不能把“白”默认当空格。

对于 A 类图纸，优先把格子代表色匹配到同一图片内的图例色块，再由图例色块关联色号。这可抵消整张截图的统一偏色。对于 B/D 类，才直接匹配品牌官方色卡。

### 3.6 阶段 5：色差与候选

- 将源色与色卡色转换到 CIELAB，用 CIEDE2000 排序。
- 保存前 3 个候选及色差，不只返回一个答案。
- 同时加入属性约束：品牌、系列、尺寸、透明/夜光/珠光等材质。
- 屏幕 RGB 或厂商色卡 RGB 只能用于近似推荐；不能据此保证实体豆完全同色。
- 近似色阈值应由真实色卡照片/测色数据和用户测试标定，不在 PRD 中硬编码通用数值。

### 3.7 阶段 6：一致性校验

至少执行六类校验：

1. 网格完整：行数 × 列数等于单元格数。
2. 用量完整：各色号格数之和等于非空格总数。
3. 图例一致：识别计数与图例标注计数逐色比较。
4. 总数一致：非空格总数与图纸标注总数比较。
5. 色卡合法：每个色号存在于所选品牌/系列。
6. 空间异常：孤立格、低置信度格、格内高离散度、边缘不齐单独列出。

一致性通过不代表每格颜色一定正确，但能显著发现边界、漏格、OCR 数量和映射错误。最终状态应分为：

- 已自动识别，待用户确认；
- 存在差异，需校对；
- 已人工确认；
- 无法可靠识别，保留原图手工建图。

## 4. 方案选择

### 4.1 MVP 推荐栈（概念方案，无代码）

| 子系统 | 首选 | 原因 | 备选 |
|---|---|---|---|
| 图像与透视 | Core Image + Vision 四角 | iOS 16 可用、设备端、隐私和包体友好 | 1.0 不引入第二管线 |
| OCR | Apple Vision VNRecognizeTextRequest | iOS 16 可用、设备端、支持候选/置信度/位置框 | 1.0 不引入第二引擎 |
| 网格检测 | Core Image/Accelerate 规则管线 | 需求专一、结果可解释 | 1.0 不引入第二管线 |
| 色彩空间 | ColorSync/Core Graphics 转换 + CIEDE2000 | 标准方法、结果可解释 | 预计算 Lab 色卡 |
| 图纸分类 | 内置规则与统计特征 | 可解释、无需训练集 | 1.0 不引入分类模型 |
| 后处理 | 色卡字典 + 业务校验 | 色号集合有限，约束强 | 小模型序列纠错 |

### 4.2 不采用 AI 大模型

- 缺少规模化、带网格/色号/坐标真值的拼豆图纸数据集。
- 大模型难以保证每一个单元格的确定性和可追溯性。
- 规则网格和有限色卡是强先验，经典视觉 + 约束求解更省成本。
- 输入分类、困难网格处理和异常候选排序均使用内置规则、统计特征和有限色卡约束；不接入通用大模型、专用生成模型或云端推理。

## 5. 文档方案可行性审查

### 5.1 保留的设计

- 框选图例区：有效，能显著降低 OCR 噪声。
- 主图/镜像图选择：有效，但镜像状态需统一到坐标系统。
- 四边网格检查：必要，网格错一列会造成系统性错误。
- 自动识别后手动调整：必要，是产品可信度的核心。
- 用标注总数核对网格总数：有效的强校验。
- 保存原图、参数与识别结果：必要，便于重新识别和算法升级。

### 5.2 修改的设计

- “自动识别色号”改为三种置信状态：图例确定、色卡推测、用户指定。
- “九宫格拆格/8×8”改为校准交互，不改变最终豆格精度。
- 识别指标从单一“完成率”拆为输入覆盖率、网格准确率、色号准确率和人工校对耗时。
- 普通照片转拼豆与现成图纸识别拆成两个产品流程和两个测试集。
- 链接取图从识别引擎拆出，作为来源适配层单独验收。

## 6. 验证数据集与测试方法

### 6.1 数据集

PoC 最少 300 张，Beta 前扩展到 1,000 张；每张必须有人工双人复核真值。

| 分组 | PoC 数量 | 变量 |
|---|---:|---|
| A 类带图例彩色网格截图 | 120 | 3+ 品牌、浅/深色、不同字号、不同网格线 |
| B 类无图例网格 | 60 | 不同颜色数、空白/白豆、透明豆 |
| C 类硬边像素图 | 40 | 整数/非整数缩放、抗锯齿、压缩 |
| 拍照/扫描图纸 | 40 | 角度、阴影、纸张弯曲、反光 |
| 失败/对抗样本 | 40 | 裁边、遮挡、低清、虚线、格内文字、摩尔纹 |

普通照片转图纸另建数据集，不计入上述识别指标。

### 6.2 真值字段

- 输入类型、有效区域四角、行列数、每个格子的空/非空和色号。
- 图例色号与标注数量。
- 品牌、系列、尺寸。
- 失败原因标签和可接受的人工干预步骤。

### 6.3 指标定义

| 指标 | 计算 | PoC 通过门槛 | Beta 建议门槛 |
|---|---|---:|---:|
| 类型分类准确率 | 正确类型/总样本 | ≥ 95% | ≥ 97% |
| 网格完全准确率 | 行列与全部交点均正确的图/可支持图 | ≥ 85% | ≥ 92% |
| 人工校准后网格准确率 | 校准后正确图/可支持图 | ≥ 98% | ≥ 99.5% |
| 图例色号字符准确率 | 正确字符/总字符 | ≥ 97% | ≥ 99% |
| 单格色号准确率 | 正确格/可识别非空格 | ≥ 95% | ≥ 98% |
| 整图完全正确率 | 所有非空格均正确的图/可支持图 | ≥ 70% | ≥ 85% |
| 差异检出率 | 被一致性校验拦截的错误图/全部错误图 | ≥ 95% | ≥ 99% |
| 误判“完全正确”率 | 错图被标为完全正确/全部错图 | ≤ 1% | ≤ 0.2% |
| 校对耗时 P50 | 从识别结果到人工确认 | ≤ 90 秒 | ≤ 60 秒 |

整图完全正确率会随图纸尺寸急剧下降，因此发布决策应更重视“误判完全正确率”和“校准后准确率”。

### 6.4 通过/停止条件

PoC 通过：A 类图纸达到表中门槛，且在目标最低机型上单张 104×104 图纸处理时间 P95 ≤ 8 秒、峰值内存不导致系统终止。  
条件通过：网格可达标但色号不足，则保留网格自动化，增加图例校对和候选选择。  
停止自动化：某输入类型整图完全正确率低于 50% 或误判完全正确率高于 2%，该类型降级为手工校准流程，不阻塞 MVP。

## 7. 关键风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| 色卡数字值不准确 | 匹配色号错误 | 建立色卡版本、来源和实物校准流程；允许用户自定义色卡 |
| OCR 易混字符 | 色号串错 | 色卡字典、Top-N 候选、逐行 UI、总数交叉校验 |
| 网格系统性偏一格 | 全图错误 | 四边锚点、周期检查、边缘残差可视化、保存前预览 |
| 白豆与空格混淆 | 总数错误 | 空白透明度/背景样本单独建模，由用户指定空格样本 |
| 格内文字污染颜色 | 颜色错误 | 内缩采样、多区域中位数、深色前景剔除、同图图例匹配 |
| 图片压缩/摩尔纹 | 线和颜色异常 | 质量门控、建议原图、局部校准、低置信度提示 |
| 实拍光照偏色 | 品牌色误配 | 灰卡/白平衡、同图图例优先、仅提供候选 |
| 算法升级改变旧图 | 库存与出库不一致 | 图纸版本锁定识别结果；升级只对副本重跑 |

## 8. 最终判断

项目文档中的识别流程在限定范围内可实施。最稳妥的 MVP 是优先支持清晰、正视、带彩色图例的规则网格图，以及人工校准后的无图例网格图。普通照片生成、代码型网格、实体豆板照片和任意第三方链接全自动识别应分期处理。

产品承诺应写成“自动完成大部分重复工作，并用差异校验引导用户确认”，不写成“任何图纸一键 100% 识别”。技术立项前必须完成 300 张标注样本的 PoC；没有真实样本测量前，当前结论属于架构可行性验证，不是精度验收完成。
